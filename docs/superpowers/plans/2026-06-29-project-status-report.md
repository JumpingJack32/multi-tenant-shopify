## 5. High-Risk / Messy Areas

### 🔴 Critical Security Issues

1. **CORS wildcard + credentials** (`services/backend-api/src/main.py:49-50`)
   - `allow_origins=["*"]` with `allow_credentials=True` — this is **invalid per the CORS spec**. Browsers will reject credentials (cookies, auth headers) when `Access-Control-Allow-Origin` is `*`. This must be changed to explicit allowed origins.

2. **Svix webhook signature NOT verified** (`services/backend-api/src/routes/webhooks.py:29`)
   - The `# TODO: Verify Svix signature` is a production vulnerability. Any request can POST to `/webhooks/svix` and trigger event processing.

3. **Shopify webhook HMAC NOT verified** (`services/backend-api/src/routes/webhooks.py:72`)
   - Same issue — `# TODO: Verify Shopify HMAC signature`.

4. **No server-side auth enforcement in admin app**
   - `proxy.ts` exists in `src/` as a Clerk middleware file, but Next.js requires `middleware.ts` at the **root** of the app directory for auto-discovery. The admin app has no middleware protection.

5. **RBAC is client-only**
   - Permissions are extracted from Clerk session claims on the client side. A user could manipulate client-side state to see UI elements their role shouldn't access. There's no server-side RBAC validation.

### 🟡 Architecture / Code Quality Concerns

6. **`@repo/ui/base-ui` import path**
   - The re-export barrel at `packages/ui/src/styles/base-ui.ts` may not export all components expected by the admin app (e.g., `Button`, `Switch`, `Drawer`). Some components have commented-out imports falling back to direct usage.

7. **Duplicate data fetching layer in admin**
   - `apps/admin/src/features/products/api/products-service.ts` and `apps/admin/src/features/products/hooks/use-products.ts` exist alongside `apps/admin/src/lib/api/client.ts`. It's unclear which is the canonical data fetching layer.

8. **`@repo/codegen` package**
   - Depends on `@hey-api/openapi-ts` for code generation, but generated files are gitignored. The package exists but can't typecheck due to missing `@types/node`. May not be needed until backend schema is stable.

9. **Storefront import path resolution**
   - Storefront components import via `@/lib/tenant-resolver` and `@/hooks/use-cart`, but these paths don't resolve correctly during typechecking, suggesting a `tsconfig.json` path alias issue.

10. **Tenant context fetch uses `NEXT_PUBLIC_API_URL`**
    - The admin tenant context fetches directly from the backend API. This means the admin app depends on the backend being running for the tenant switcher to work. No graceful fallback.

11. **`is_platform_superuser` flag exists but no platform routes**
    - The DB field exists, the test exists, but there are no API endpoints, no Clerk webhook handler for org membership sync, and no JWT template configured in Clerk dashboard to include this claim.

12. **IgnoreDeprecations syntax error across 5 tsconfigs**
    - `"ignoreDeprecations": "6.0"` should be `"ignoreDeprecations": ["6.0"]` (the TS 7.0 deprecation warning expects an array). This is a minor fix that blocks clean typecheck.

### 🟢 Minor Issues

13. **Commented-out code in product-form.tsx** — lines 166-173 have a ghost/outline button variant block commented out.
14. **Storefront `use-cart.ts`** — `any` types on reducer parameters (minor, 3 warnings).
15. **Storefront `QueryClientProvider`** — commented out in layout.tsx.
